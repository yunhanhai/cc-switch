# YunSwitch

Claude Code、Codex、Gemini CLI などの設定管理とローカルルーティングを、継続的に改善するプロジェクトです。

**メンテナー：yunhanhai** · **ライセンス：[MIT](LICENSE)**

[English](README.md) | [中文](README_ZH.md) | 日本語 | [Deutsch](README_DE.md)

## このプロジェクトについて

本リポジトリは、[farion1231/cc-switch](https://github.com/farion1231/cc-switch) の **v3.20.1** を基に、yunhanhai が独立して保守・追加開発している派生プロジェクトです。
上流の設定管理、プロトコル変換などの基盤を引き継ぎ、複数のプロバイダーを日常的に利用するためのルーティングと復旧処理を強化しています。

今後は、他のオープンソースプロジェクトの設計や機能も参考にしながら改善を進めます。
取り込むコードの出典とライセンスを記録し、このリポジトリの変更内容とリリースを独立して管理します。

- [Gitee リポジトリ](https://gitee.com/yunhanhai/yunswitch)
- [GitHub リポジトリ](https://github.com/yunhanhai/yunswitch)
- [プロジェクトの出典・バージョン・保守計画](docs/PROJECT.md)

## 追加開発の内容

| 機能                    | このリポジトリでの強化                                                                   |
| ----------------------- | ---------------------------------------------------------------------------------------- |
| ルーティンググループ    | アプリごとにプロバイダーをグループ化し、順序変更、実効ルートのプレビュー、状態表示を提供 |
| モデルエイリアス        | 同じ論理モデルを、プロバイダーごとに異なるモデル名へ変換し、切り替え時にも適用           |
| Gemini のモデル指定     | URL 内のモデル名を書き換え、プロバイダー切り替えと整合させる                             |
| モデルカタログ          | プロバイダーのモデル一覧、補助データ、キャッシュを使って設定とマッピングを支援           |
| Claude → Codex 設定変換 | API 設定とモデル名を引き継ぎ、重複作成を防止し、利用条件を表示                           |
| 障害への対応            | 同じプロバイダーへの再試行、429 の待機・クールダウン、フェイルオーバーの状態表示を強化   |

設定変換は、上流から引き継いだプロトコル変換の基盤を利用します。
ブリッジモードでは、先にローカルルーティングを起動してください。
直接接続への切り替え判定はモデル一覧の取得と元のモデルの存在確認に基づき、`/responses` の動作確認までは行いません。

同じプロバイダーへの再試行は初期設定では無効です。接続失敗や一部の一時的な HTTP エラーを対象とし、すでにクライアントへ渡したストリームは再送しません。

## 現在のバージョンと入手方法

ソース内の `3.20.1` は、引き継いだバージョンを示します。本プロジェクト独自の正式リリース番号ではありません。
現在、GitHub Releases に本プロジェクトの配布物はありません。開発する場合はソースから起動してください。
上流のインストーラーやパッケージ管理コマンドは、本リポジトリの追加機能を配布するものではありません。

## ソースから開発する

Node.js、pnpm、Rust、および利用する OS の Tauri 開発環境を準備してください。
詳細は [開発・貢献ガイド](CONTRIBUTING.md) を参照してください。

```bash
git clone https://gitee.com/yunhanhai/yunswitch.git
cd yunswitch
pnpm install --frozen-lockfile
pnpm dev
```
