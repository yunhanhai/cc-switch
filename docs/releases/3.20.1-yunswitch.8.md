# YunSwitch 3.20.1-yunswitch.8 Windows x64 预发布

2026-11-14，Windows x64 在 [GitHub](https://github.com/yunhanhai/yunswitch/releases/tag/v3.20.1-yunswitch.8) 和 [Gitee](https://gitee.com/yunhanhai/yunswitch/releases/tag/v3.20.1-yunswitch.8) 同步公开。源码 `3.20.1-yunswitch.8`，MSI `3.20.1.8`，沿用独立身份、数据目录及 UpgradeCode。上版 [`.7`](3.20.1-yunswitch.7.md) 保留原附件。后续优先级见[开发路线](../DEVELOPMENT-ROADMAP.md)。

## 本版变化

- 已限流请求使用每应用/供应商独立恢复许可，同一供应商的输出前恢复逐个进行，不同供应商互不阻塞。
- 获取许可和每次醒来后重新检查共享截止时间，后来延长的限流窗口不会被已有短等待忽略。再次限流时先登记新截止时间再释放许可。
- 排队和期限延长受已有单次等待上限约束，超限返回 429 和等待提示；取消、超时、失败自动回收许可。
- 输出前检查完成并交付后释放许可，长流不会阻塞后续恢复。延长同一次等待只更新计划时长，不多计一次重试。
- 新增开发路线，后续按脱敏请求诊断、真实接入与长会话矩阵、协议场景、平台发布和单项开源能力接入推进。

## 使用边界

使用既有等待开关与单次上限。只有已遇到 429 的可重放请求进入恢复协调，普通首次请求不统一排队；原生状态型 Codex 仍保护一次发送，已有文本或工具活动后不重放。新机制不是对所有 API 流量设置总并发上限，也不保证真实供应商不再限流。

仅发布 Windows x64，发布者签名与自动更新仍关闭。真实网站、套餐、长会话和其他平台安装需逐项验证，按[开发路线](../DEVELOPMENT-ROADMAP.md)继续推进。
