# YunSwitch 3.20.1-yunswitch.8 Windows x64 预发布准备

本版准备补强限流后的恢复节奏。源码 `3.20.1-yunswitch.8`，MSI `3.20.1.8`；当前公开版本仍为 [`.7`](3.20.1-yunswitch.7.md)。后续开发优先级见[开发路线](../DEVELOPMENT-ROADMAP.md)。

## 本版变化

- 已遇到 429 的请求使用每应用、每供应商独立的恢复许可。同一供应商的输出前恢复尝试逐个执行，其他供应商互不阻塞。
- 等待获取许可和每次醒来后重新检查共享冷却期限，后来的限流要求不会被先前的一秒等待忽略。
- 排队与共享期限延长受现有单次等待上限约束；超限返回 429 与等待提示，并按已有候选预算处理。
- 取消、超时及失败自动释放恢复许可；一旦响应输出前检查成功并交付，许可释放，避免长流阻塞后续请求。
- 等待期限延长更新现有状态与计划等待统计，不增加额外的重试次数。补充并发、期限延长、取消、超时和实际 Windows 程序检查。

## 验证状态

准备中。完成源码回归、严格 Clippy 和跨平台 CI，再构建新 Windows 包验证便携版与 `.7` 升级。产物、校验值和公开入口随后记录。

## 使用边界

使用已有 429 等待开关和单次等待上限，旧默认设置保持。只有已经遇到 429 的可重放请求进入恢复协调，普通首次请求不统一排队；状态型 Codex 请求仍按 `.7` 保护一次发送。输出交付后不重放，长流不持有恢复许可。此机制不能保证真实供应商不再限流，实际套餐和长会话需分别验证。

Windows x64 发布者签名与自动更新仍关闭；其他平台安装包验收、请求诊断与真实接入矩阵按[开发路线](../DEVELOPMENT-ROADMAP.md)继续推进。
