# YunSwitch 3.20.1-yunswitch.7 Windows x64 预发布准备

本版修复自动重试的状态边界及并发冷却记录。源码 `3.20.1-yunswitch.7`，MSI `3.20.1.7`；当前公开版仍为 [`.6`](3.20.1-yunswitch.6.md)，需要完成最终 CI 和 Windows 新包验收后发布。

## 本版变化

- 原生 API Key Codex Responses 的后台任务、会话/响应引用、压缩历史与服务器执行工具请求遇到 HTTP 错误或断连后只发送一次，不进入同家重试、整流重试或备用供应商重发。
- 成功只清除本次发送前已知的冷却窗口，较早发出的请求不能抹掉并发请求后来登记的限流；最后不足一秒的冷却仍保持有效。
- 明确 `insufficient_quota` / `billing_hard_limit_reached` 等结构化额度错误不进入 429 等待循环，按已有额度耗尽策略处理。普通消息中提到“quota”不会因此被判为额度耗尽。
- 重复 `Retry-After` 使用最长有效值；缺少有效响应头时读取错误对象的 `retry_after_seconds` / `retry_after`。数字超出范围时按超长等待处理，避免误退回一秒重试。
- Windows 便携版及 `.6` 升级后新增状态请求一次发送、429 等待提示保留、并发冷却、重复等待头与额度耗尽检查。

## 验证与发布

准备中。先完成本地代理回归、严格 Clippy、跨平台 CI、实际 Windows 包运行和 `.6` MSI 升级，再记录源码、校验值与下载入口。测试仅使用虚构密钥、合成请求和回环上游。

## 使用边界

此次保护针对原生 API Key Codex Responses。官方账号和跨协议转换继续使用原有实现；也不为已经发出文本或工具活动后的断流重放请求。冷却用于选路优先级，并非跨请求排队节流。真实 API 网站、长会话和其他平台安装仍需单独验证。重试偏好保持用户选择，Windows x64 签名与自动更新仍关闭。
