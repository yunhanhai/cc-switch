# Codex Responses 输出前错误恢复

`.5` 准备源码在原生 Codex Responses 入口增加首段检查。`.4` 安装包保留原有流内错误处理；本轮构建与实际验收状态见[`.5` 发布记录](releases/3.20.1-yunswitch.5.md)。

## 处理的问题

部分网关先返回 HTTP 200 和 `response.created`，随后发送 `response.failed` 或 `error`。此前原生 Codex 路径把 HTTP 成功当成转发成功，流内限流或服务故障到达客户端后才被发现，代理无法再尝试同一家或备用供应商。

新的检查在响应交付前识别明确的错误字段，复用已有 429 等待、同一供应商重试和故障转移设置。不启动额外服务，也不修改加密历史兼容开关或重试偏好。

## 生效范围与设置

适用于经 YunSwitch 本地路由使用 API Key 的原生 Codex `/responses`、`/v1/responses` 请求，不按网站域名限制。识别 SSE 和 JSON，含未标注 Content-Type 的可识别响应；压缩响应不执行这一首段检查，继续由已有响应路径处理。

设置入口为**设置 → 路由 → 故障转移 → Codex**：

- **429 限流等待重试**默认关闭。明确流内限流复用单次等待上限和每家最多 10 次等待；优先使用 HTTP `Retry-After`，其次使用错误对象的 `retry_after_seconds` / `retry_after`，缺失时复用已有退避。
- **同一供应商重试**默认 0 次。明确流内服务端暂时错误使用既有次数与退避，用完预算后按故障转移设置处理。
- 故障转移关闭时仍可独立使用限流等待或同家重试。备用供应商必须有匹配模型和可用配额。

该检查与[加密历史兼容](CODEX-RESPONSES-COMPATIBILITY.md)独立：兼容开关只影响出站历史清理；关闭它时，不兼容密文的明确流内错误会作为 400 返回并给出指引。

## 恢复边界

| 信号或场景                                                               | 处理                                                    |
| ------------------------------------------------------------------------ | ------------------------------------------------------- |
| 生命周期事件后，明确 `rate_limit_exceeded` / `rate_limit_error`          | 按限流设置等待重试；不允许等待时返回 429 或按配置转移   |
| 明确 `server_error`、`internal_error`、`overloaded_error` 等             | 对应 502/503，再按同家重试或故障转移处理                |
| 余额耗尽、鉴权或模型访问错误                                             | 不盲目重试同一家，按既有策略处理；额度耗尽不会误当限流  |
| 无效参数、上下文超限、不兼容密文                                         | 返回明确 400，保留可识别错误码；不重试同家              |
| 文本、推理、工具活动、完成/不完整/取消、未知事件                         | 立即原样交付；此后不重试此响应，避免重复输出或工具调用  |
| 错误对象带已有输出或输出 token                                           | 保持原样交付，不能假定可无副作用重放                    |
| `background`、`conversation`、`previous_response_id`、压缩历史或引用条目 | 不套用新恢复检查；状态和副作用不能安全重建              |
| 上游执行的 web search、MCP、computer 等工具                              | 不套用新检查；仅普通客户端 function/custom 工具请求参与 |
| 官方账号/OAuth、跨协议 Chat/Anthropic、compact 或其他客户端              | 沿用原有路径，本轮未扩展                                |
| 已经输出后的断流                                                         | 由客户端处理，不拼接、不重放，不保证编程代理继续任务    |

首段检查最多等待 5 秒（已配更短首包超时可缩短），最多缓存 256 KiB 或 1024 个数据块。心跳不重置截止时间。到达检查上限后将缓存字节和后续响应原样交付；未知或损坏格式也原样交付。后续超时继续由原有响应处理负责。

错误分类只使用结构化字段，不按上游消息中的关键词猜测。诊断采用固定文本和已知错误码，不回显私人错误内容。失败尝试的生命周期和错误事件不混入最终成功响应。

## 验证范围

单元测试覆盖分片、UTF-8/BOM、JSON、CRLF、错误分类、截止时间和缓存上限、原样回放。回环上游测试核对实际请求次数、限流设置、同家重试预算、失败后转移、输出/工具活动后的禁止重试、私人消息不回显；真实代理入口验证 429 状态与等待头及限流后成功。

Windows 包验收在便携和升级后安装程序中验证流内 429、暂时服务错误和输出后失败。只用合成历史、虚构密钥、回环上游，不代表所有 API 网站或长会话均已验证。

官方文档请求在本轮环境返回 403，未据未读取的网页宣称全部协议兼容。实现依照仓库已有 Responses 结构与可复现测试，保守透传未知扩展。
